## Objectives
Use `dir()`, `help()`, `inspect.signature()` to explore any library; navigate the MCP SDK; explain async/await and the event loop; explain why MCP servers are async.

## Two foundations

**1. Inspection over memorization.** Libraries are large and change. The durable skill is interrogating a library live:
- `dir(obj)` — what's in here (attributes/methods)
- `help(obj)` — what does this do (docstring)
- `inspect.signature(fn)` — what arguments does it take

```python
import mcp, inspect
print([n for n in dir(mcp) if not n.startswith('_')])
from mcp.server.fastmcp import FastMCP
help(FastMCP)
print(inspect.signature(FastMCP.__init__))
print(inspect.signature(FastMCP.tool))
```

**2. Why async.** MCP servers spend most of their time *waiting* — for a message, a database, an API call. Synchronous code waits by *blocking* (frozen, can't do anything else). Asynchronous code waits by *yielding* ("I'm waiting, use the time for something else"). For a server handling many messages, this is essential — which is why the SDK is async throughout.

### Async essentials
- `async def` — defines a coroutine (an awaitable function)
- `await` — "wait for this, but let other work run meanwhile" (only usable inside `async def`)
- **event loop** — the scheduler that runs many coroutines, switching between them at each `await`

```python
import asyncio

async def slow_add(a, b):
    await asyncio.sleep(1)   # yields while waiting; not frozen
    return a + b

async def main():
    # Three concurrent calls -> ~1s total, not 3s
    return await asyncio.gather(slow_add(1,1), slow_add(2,2), slow_add(3,3))

print(asyncio.run(main()))   # [2, 4, 6]
```

## Mental Model
**Inspection = asking a shopkeeper** what they sell, what an item does, what you need to buy it. **Async = one waiter, many tables** — takes an order, and while the kitchen cooks (the `await`), serves other tables. Time spent waiting is reused.

## Why MCP is async
A protocol server is I/O-bound (mostly waiting on network/disk). For I/O-bound work, async is lighter and safer than threads — no thread-pool overhead, far fewer race conditions, scales to many connections cheaply. **Caution:** a blocking call (`time.sleep`, a synchronous DB driver) inside async freezes the whole loop — avoid it.

## Key Takeaways
- Inspect, don't memorize: `dir` / `help` / `inspect.signature`.
- Async waits by *yielding*, not *blocking* — the server stays responsive while waiting.
- `async def` = coroutine; `await` = wait-but-yield; the event loop schedules them.
- A blocking call inside async freezes the whole loop.
