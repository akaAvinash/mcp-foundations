# Lesson 2.5 — Protocol-Level Debugging

**2.5 hours · Advanced · Prereq: 2.1–2.4**

When an MCP integration misbehaves, diagnose from the raw JSON-RPC stream. The messages don't lie.

## The method
1. **Capture** the message stream (Inspector log, or your own logger)
2. **Locate the divergence** — the first message that's wrong, missing, or out of order. The fault is at or just before it; everything after is downstream noise
3. **Classify** into a failure category (below)
4. **Hypothesize and test** — change one thing, re-capture

## The failure taxonomy
- **Framing/parse** — invalid JSON, or messages not delimited (on STDIO, a stray `print()` to stdout)
- **Correlation** — response `id` doesn't match any request; ids reused or altered
- **Ordering/lifecycle** — operations before `initialized`, or `initialized` before `initialize`
- **Serialization** — a non-JSON value (Python object, NaN) put into a message
- **Capability** — using a feature the other side never advertised
- **Version** — client/server can't agree on a protocol version
- **Semantic/schema** — arguments valid JSON but violating the tool's inputSchema (`-32602`)

## Three-pass log reading
1. **Structure** — tag each line request/response/notification; a line fitting none is a framing clue
2. **Correlation** — pair each request `id` with its response; orphans/unanswered are clues
3. **Sequence** — verify lifecycle order

Most bugs surface in these three passes, before you even read message contents.

## STDIO gotcha
On STDIO, stdout IS the wire — logging or `print()` there corrupts the stream. Always log to **stderr**.

## Mental Model
Crime-scene investigation: the log is the evidence; follow it to the first anomaly. The taxonomy is your list of known M.O.s. Establish *where/when* the break occurs before theorizing *why*.

## Key Takeaways
- The messages are ground truth; locate the first divergence before theorizing.
- Faults fall into known classes — framing, correlation, ordering, serialization, capability, version, schema.
- Three passes (structure → correlation → sequence) find most bugs.
- Distinguish symptom from cause; drop to the protocol level for hard bugs.
