# Lesson 2.4 — MCP Inspector Deep Dive

**1.5 hours · Intermediate · Prereq: 2.1–2.3**

The MCP Inspector is DevTools for MCP — it connects to your server, performs the handshake, discovers your tools, and lets you call them while showing the raw JSON-RPC traffic.

## Launch it
```bash
npx @modelcontextprotocol/inspector --help
npx @modelcontextprotocol/inspector python your_server.py   # STDIO
# or connect to a Streamable HTTP URL in the connection panel
```

## The panels (map to protocol concepts)
- **Connection** — choose transport (STDIO command or Streamable HTTP URL); connecting triggers the handshake (2.2)
- **Server info / capabilities** — from the `initialize` response
- **Tools** — the result of `tools/list` (2.3), each rendered as a form from its schema
- **Message log** — the raw JSON-RPC stream: your most important debugging surface

## Guided session
1. Connect with the log open → watch initialize / response / initialized fire
2. Open Tools → confirm each tool appears with a schema-generated form
3. Call a tool → read the result AND find the `tools/call` request/response pair in the log by `id`
4. Narrate the whole session from the log alone — that fluency is the goal

## Mental Model
Browser DevTools' Network tab, but for MCP: friendly panels on top, raw message log underneath.

## Key Takeaways
- The Inspector's panels map directly to the handshake (2.2) and discovery (2.3).
- Tool forms are generated from `inputSchema` — they can only produce schema-valid arguments.
- The message log is your primary debugging surface; learn to read it as a narrative.
- Panel layout is version-dependent; the protocol concepts underneath are stable.
