# Lesson 3.1 — Building Robust Tools

**3 hours · Intermediate · Prereq: Phase 1, Phase 2**

A tool is called by an unpredictable LLM. A robust tool assumes nothing and defends everything.

## Three pillars
1. **Validate inputs** — the schema catches type errors; your code checks *meaning* (ranges, paths, lengths). Validate first, before doing work.
2. **Fail with structure** — return a clear error, never an uncaught crash or leaked traceback.
3. **Guard the outside world** — file, DB, and API tools are where security lives or dies.

## Path traversal (file tools)
A path like `../../etc/passwd` can escape the intended directory. **Defense:** resolve the path to canonical absolute form and verify it's still inside the allowed base directory.

## SQL injection (DB tools)
String-concatenating user input into SQL lets attackers inject. **Defense:** parameterized queries (`?` placeholders with values passed separately) so the DB treats input as data, never SQL.

## The verified code

```python
from pathlib import Path
import sqlite3
from mcp.server.fastmcp import FastMCP

server = FastMCP("robust")
BASE_DIR = Path("./safe_base").resolve()

@server.tool()
def read_file(relative_path: str) -> str:
    """Read a text file from the safe directory."""
    target = (BASE_DIR / relative_path).resolve()
    if not target.is_relative_to(BASE_DIR):          # traversal guard
        raise ValueError("Access denied: path escapes the allowed directory.")
    if not target.is_file():
        raise ValueError(f"Not a readable file: {relative_path}")
    return target.read_text(encoding="utf-8")

@server.tool()
def find_user(name: str) -> list[dict]:
    """Look up users by exact name."""
    if not (1 <= len(name) <= 100):
        raise ValueError("name must be 1-100 characters.")
    conn = sqlite3.connect("app.db")
    rows = conn.execute("SELECT id, name FROM users WHERE name = ?", (name,)).fetchall()  # parameterized
    conn.close()
    return [{"id": r[0], "name": r[1]} for r in rows]
```

**Both defenses are verified by the test suite** ([`../../code/tests/test_robust_tools.py`](../../code/tests/test_robust_tools.py)): a traversal attempt is blocked, and a SQL-injection string is treated as literal data (the table survives).

## Mental Model
A robust tool is a **nightclub with a bouncer**: the schema is the dress code at the door; your validation is the bouncer checking IDs and refusing weapons (`../`, `'; DROP TABLE`), giving a clear reason when someone's turned away.

## Key Takeaways
- Schema checks shape; your code checks meaning — validate in-function, first.
- Always fail with a clear structured error.
- Path traversal → resolve + confirm inside the base directory.
- SQL injection → parameterized queries, never concatenation.
- LLM-supplied input is hostile-until-proven-safe.
