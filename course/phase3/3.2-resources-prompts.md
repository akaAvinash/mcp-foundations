# Lesson 3.2 — Resources & Prompts

**2.5 hours · Intermediate · Prereq: Phase 1, 3.1**

Tools are actions. Resources are readable context. Prompts are reusable templates. The three primitives divide by control and effect:

| Primitive | Control | Effect |
|-----------|---------|--------|
| Tools | Model-controlled | Actions (side effects) |
| Resources | App-controlled | Read-only data |
| Prompts | User-controlled | Parameterized templates |

## Resources
Identified by a **URI** (`config://app`, `user://{id}`). Two kinds:
- **Static** — fixed URIs
- **Dynamic/templated** — `user://{user_id}` where the host fills the parameter

Deciding rule: side-effect-free read → resource; action with effects → tool.

## Prompts
Named, parameterized templates. The server author encodes the good phrasing once; every user gets it.

## The verified code

```python
from mcp.server.fastmcp import FastMCP
server = FastMCP("library")

@server.resource("config://app")
def app_config() -> str:
    """The application's configuration (read-only)."""
    return "theme=dark\nlanguage=en\nversion=1.0"

@server.resource("user://{user_id}")
def get_user(user_id: str) -> str:
    """A user's profile by id (templated resource)."""
    return f"Profile for user {user_id}"

@server.prompt()
def summarize(text: str, style: str = "bullets") -> str:
    """A prompt that summarizes text in a chosen style."""
    return f"Summarize the following in {style}. Be concise:\n\n{text}"
```

## Mental Model
A **reference library**: tools are the librarian who *does* things; resources are books on the open shelves you read freely; prompts are ready-made request forms at the desk.

## Key Takeaways
- Three primitives by control/effect: tools (model/actions), resources (app/read-only), prompts (user/templates).
- Deciding rule: side effect → tool; safe read → resource; reusable way-to-ask → prompt.
- Resources use URIs; dynamic URIs use `{param}` templates.
- Dynamic resource parameters are user input — validate them like tool inputs.
